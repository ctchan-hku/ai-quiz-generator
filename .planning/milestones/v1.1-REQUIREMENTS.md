# Requirements — v1.1 (generation quality & control)

**Version:** v1.1  
**Last updated:** 2026-04-30  
**Status:** Complete — Phases **6–9** satisfied (single milestone scope)  
**Builds on:** [v1.0 archive](milestones/v1.0-REQUIREMENTS.md)

---

## Theme

Improve quiz generation **quality and steerability**: few-shot examples, math-capable catalog entry, per-question refinement, optional **user instruction lines**, and **reasoning-first MCQs** with server-side option shuffle.

---

## MOD — Model catalog

- [x] **MOD-01**: Default / documented model list includes **`gpt-4.1`** with a label indicating stronger math/reasoning.
- [x] **MOD-02**: `GET /api/models` exposes only configured ids; generate and regeneration reject unknown model ids with **422**.

---

## AI — Few-shot examples (full-quiz generation)

- [x] **AI-FS-01**: `POST /api/generate/quiz` accepts optional **`few_shot_examples`**: `list[str]`, max **3**, each max **2_000** characters.
- [x] **AI-FS-02**: Non-empty few-shot content is injected into the **system** message; instructs the model to match tone, difficulty, and format of examples.
- [x] **AI-FS-03**: Few-shot content is included in the initial `messages` passed to `parse_with_retry`.
- [x] **AI-FS-04**: UAT / automated coverage documents behaviour with and without examples (`06-UAT.md`, `test_few_shot_examples.py`).

---

## AI — Per-question regeneration

- [x] **AI-RG-01**: **`POST /api/generate/question`** accepts **`model`**, **`topic`**, **`question`** (`MultipleChoiceQuestion`), optional **`comment`** (max **2_000**); no quiz array, sibling context, or separate instruction field.
- [x] **AI-RG-02**: Response body is a validated **`MultipleChoiceQuestion`** (FastAPI **response_model** — top-level MCQ JSON, same fields as quiz items; no `{ "question": … }` wrapper).
- [x] **AI-RG-03**: LLM uses **json_object** mode; **system** + **user** messages include topic, target question only, and comment / neutral default per **07-CONTEXT**.
- [x] **AI-RG-04**: **Shared** **3 requests / IP / hour** limit with **`POST /api/generate/quiz`** (`shared_limit` scope).
- [x] **AI-RG-05**: On validation failure, **one** corrective retry then **502** if still invalid.

---

## AI — User instructions (Phase 8)

- [x] **AI-INST-01**: **`POST /api/generate/quiz`** accepts optional **`user_instructions`**: `list[str]` with server normalization (max lines, max chars per line → **422** on violation).
- [x] **AI-INST-02**: **`FullQuizLlm`** merges formatted user lines with question-class instructions in the system prompt **before** the few-shot appendix (`USER_INSTRUCTIONS_FORMATTER` + segment order in `full_quiz.py`).
- [x] **AI-INST-03**: Omission or all-empty lines omits **`user_instructions`** from the effective payload (same semantics as few-shot).

---

## AI — Reasoning-first MCQ, shuffle (Phase 9)

- [x] **AI-Q9-01**: **`MULTIPLE_CHOICE_CONSTRAINTS`**, **`MCQ_CHAIN_OF_THOUGHT`**, and **`REWRITE_HINT`** require stem clarity, correct answer before distractors, plausible distractors, and **stepped** explanations with soft length guidance (`mcq_constraints`).
- [x] **AI-Q9-02**: **`QUIZ_SOURCE_PRIORITY_GUIDANCE`** plus conditional **user** message emphasis when few-shot examples exist (topic as coverage; examples steer tone/shape).
- [x] **AI-Q9-03**: After **`model_validate`**, **`shuffle_option_order`** permutes **`options`** and remaps **`correct_indices`** for **full quiz** and **single MCQ** responses (`secrets.SystemRandom`).

---

## FE — Few-shot UI

- [x] **FE-FS-01**: Optional **Example / style hints** control with up to **3** inputs.
- [x] **FE-FS-02**: Examples sent only on **Generate**; session state only unless a later milestone adds persistence.
- [x] **FE-FS-03**: Loading/error behaviour unchanged aside from optional field on generate.

---

## FE — Regenerate question UI

- [x] **FE-RG-01**: Per-question **Refine** flow with **Confirm** / **Cancel** and **Comment** on the card.
- [x] **FE-RG-02**: Successful refine **appends** a version and selects it; quiz-level **`model_used`** unchanged by default; refinement uses current form model.
- [x] **FE-RG-03**: Per-card loading; failures do not discard the quiz.
- [x] **FE-RG-04**: Export/journal uses **selected** version per slot.
- [x] **FE-RG-05**: Client-side version stacks per index (session-only).
- [x] **FE-RG-06**: Version **`<select>`** on each card.
- [x] **FE-RG-07**: **`comment`** is the only free-text refinement channel to **`POST /api/generate/question`**.

---

## FE — User instructions UI (Phase 8)

- [x] **FE-INST-01**: Compact **Quiz-specific instructions** rows (`UserInstructionsLinesSection`), single-line inputs with per-line **`maxLength`** and capped row count.
- [x] **FE-INST-02**: **`generateQuiz`** sends **`user_instructions`** only when non-empty after normalize.
- [x] **FE-INST-03**: Shorter topic/cover textarea (layout per **08-CONTEXT**).

---

## DEPLOY — Ops

- [x] **DEPLOY-04**: README and **`.env.example`** document **`AVAILABLE_MODELS`** including **gpt-4.1** and provider-specific ids.

---

## Out of scope (v1.1)

- Document upload track (deferred).
- New question types beyond **multiple_choice** in generation or regeneration.
- Batch regeneration of the whole quiz in one call.
- Server-side persistence of few-shot or instruction presets.
