<objective>
Ship Phase 9 backend: (1) **prompt + outline** changes so stems, keyed answers, stepped explanations, and plausible distractors follow a clear reasoning order; (2) **user vs system messaging** so few-shot/example lines steer tone and format while **topic** stays directional; (3) **server-side shuffle** of `options` with remapped `correct_indices` after successful parse for both full quiz and single-question refinement; (4) **tests + README** updates.
</objective>

<threat_model>
### Threats & mitigations
- **Training data in user content**: Topic and examples are already untrusted; no `eval`. Shuffle uses `secrets` only for permutation — no new injection surface.
- **Oversized explanations**: Soft cap in prompt; monitor token usage; optional follow-up to add `Field(max_length=...)` on `explanation` if needed.
- **Regression on validation**: Run full `pytest`; extend tests for shuffle invariants (length preserved, correct set preserved as labels).
</threat_model>

<title>Shuffle helper + wire `parse()` for Quiz and Single MCQ</title>
<read_first>
- backend/app/helpers/options.py
- backend/app/models/schemas.py
- backend/app/services/llm/full_quiz.py (`parse`)
- backend/app/services/llm/single_mcq.py (`parse`)
</read_first>
<action>

1. Add **`shuffle_option_order(options: list[str], correct_indices: list[int]) -> tuple[list[str], list[str]]`** in the **options helper** at **`backend/app/helpers/options.py`**, alongside **`truncate_options`**:

   - Let **`order = list(range(n))`**, **`rng = secrets.SystemRandom()`**, **`rng.shuffle(order)`**. Interpret **`order[k]`** as **which old index** moves to **new slot `k`**: **`new_options[k] = options[order[k]]`**.
   - For each old correct index **`c`**, its new slot is **`order.index(c)`** (the unique **`k`** with **`order[k] == c`**). Build **`new_correct_indices`** as a sorted list of those new slots (ascending), matching current duplicate checks on the model.

   - Assert in tests `len(new_options) == len(options)` and set equality of multiset of texts.

2. **`FullQuizLlm.parse`**: after **`Quiz.model_validate(data)`**, map each question with **`question.model_copy(update={...})`** or reconstruct **`MultipleChoiceQuestion`** with shuffled **`options`** / **`correct_indices`** (prefer **`model_copy(update=…)`** on validated instances).

3. **`SingleMcqLlm.parse`**: after **`MultipleChoiceQuestion.model_validate(result)`**, apply the same shuffle helper once.

4. Do **not** shuffle inside Pydantic validators (avoids surprising validation-order coupling).

</action>
<acceptance_criteria>
- New unit tests: shuffle preserves multiset of option strings and maps correct_indices correctly (use **fixed RNG** monkeypatch **`secrets.SystemRandom.shuffle`** or inject permutation for deterministic test).
- `python -m pytest backend/tests -q` passes.
</acceptance_criteria>
